# Mallowstead 0.1.4d-cognitive — Authored World Hotfix

## Status

Implemented on top of `0.1.4d-cognitive`.

Version remains `0.1.4d-cognitive`.

## Scope

This is an authored-world-only hotfix. It does not change engine/runtime logic, AI protocols, migrations, schemas, weather mechanics, equipment mechanics, scheduling, or version metadata.

The hotfix addresses three playtest findings:

1. remove concrete current-weather prose from static authored locations;
2. make the farmhouse stove's working side unambiguous;
3. give Radovan, Bozhena, and Zlata canonical equipped clothing.

## 1. Static authored world must not assert current weather

### Problem

The authored world itself does not define canonical `world.environment` runtime state; current weather is already initialized and maintained by the existing runtime weather system.

However, two static location descriptions still hard-code the original scene's rain:

- `street`: `Cold rain falls upon the village street.`
- `villageTemple`: `...smelling of cold incense and rain.`

Because location descriptions are stable authored facts, this contradicts runtime weather whenever conditions change.

### Change

Replace those concrete current-weather statements with weather-neutral physical description.

Do not change conditional or enduring references to weather such as clothing made for bad weather, shelter, or household behavior in severe cold. Those are not assertions about current conditions.

### Acceptance

- Static location descriptions do not assert that it is currently raining.
- Runtime `environment.weatherNarrative` remains the sole current-weather description.
- Existing startup and timelapse weather behavior is unchanged.

## 2. Farmhouse stove grounding

### Problem

The farmhouse description says the large stove serves both rooms, but does not clearly state where its operating side is. During play Bozhena remained in `farmhouseLiving` while narrating adding kindling and preparing to hang a kettle.

The intended physical layout is:

- the stove spans/heats both rooms;
- the firebox, cooking openings, fuel handling, and kettle/pot hardware are accessible only from `farmhouseUtility`;
- `farmhouseLiving` receives only the heated masonry mass and sleeping platform.

### Change

#### `farmhouseUtility`

Explicitly state that:

- the firebox and cooking openings face this room;
- fuel, kindling, lighting, stoking, kettle/pot handling, and cooking happen here;
- only the heated body and sleeping platform project into the living room.

#### `farmhouseLiving`

Explicitly state that:

- only the warm masonry body and sleeping platform project into the room;
- there is no firebox or cooking access on this side;
- tending or cooking on the stove requires moving to the utility room.

### Non-goal

Do not add a mechanical stove-access action or hard engine constraint. This is physical grounding through authored description only.

## 3. Farmer household clothing

### Problem

`radovan`, `bozhena`, and `zlata` had no authored equipped clothing instances. The appearance system therefore correctly exposed them as undressed.

### Change

Add ordinary canonical clothing definitions and equipped item instances following the existing clothing pattern:

- `radovanClothing` / `radovanClothing_01`
- `bozhenaClothing` / `bozhenaClothing_01`
- `zlataClothing` / `zlataClothing_01`

All three definitions:

- use `familyId: "clothing"`;
- include the `clothing` tag;
- use equip slot `clothing`;
- are non-consumable, equippable authored clothing;
- provide grounded `equippedDescription` text.

The instances start equipped by their corresponding characters.

### Characterization

- Radovan: plain durable field/yard work clothes.
- Bozhena: sturdy everyday homespun dress and work apron.
- Zlata: simple practical household/farm clothes, described ordinarily and non-sexually.

## Migration behavior

No migration-code change is required. Existing migration starts from the current authored world and overlays compatible saved runtime state, so the newly authored farmer clothing appears when an older compatible save is migrated.

The `0.1.4d-cognitive` migration also intentionally drops legacy flat-five intimate anticipation contexts rather than inferring them into the new cognitive format.

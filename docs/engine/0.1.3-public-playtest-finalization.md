# Mallowstead 0.1.3-public — Public Playtest Finalization

## Status

Implemented final corrective specification for the `0.1.3-public` public build.

This specification contains exactly two product changes:

1. preserve world-state authority/provenance through the memory-maintenance pipeline so narration cannot be consolidated as canonical tracked fact;
2. correct Chuhaister's authored eye appearance.

No other gameplay, retrieval, intimacy-mode, action-contract, or world-system redesign belongs in this patch.

---

# Part I — Engine: Memory Authority Propagation

## Problem

Mallowstead already distinguishes model-facing observations by authority.

For tracked world-state facts:

- canonical world state is authoritative;
- grounded engine/action results are authoritative;
- free-form narration is non-authoritative.

The Character protocol already communicates that previous narration does not prove a tracked action occurred.

However, this authority distinction is currently lost before memory maintenance/consolidation.

### Observed failure

A Character narrated that Garrick had served Banush even though no corresponding formal tracked operation had succeeded.

Canonical world state correctly did not contain the served Banush result.

The immediate Character context could distinguish narration from grounded results.

But when observations were later passed into memory maintenance through the verbatim snapshot/history path, narration and grounded events were flattened into effectively equivalent event records.

The memory-maintenance model therefore had no reliable provenance signal telling it:

- "Garrick narrated that the Banush was served"

versus:

- "the engine confirms that Garrick served the Banush."

As a result, non-authoritative narration was consolidated into memory as if it were canonical fact.

This can contaminate:

- STM;
- LTM;
- beliefs;
- later retrieval;
- future Character decisions.

---

## Architectural requirement: Authority survives the full memory pipeline

World-state authority/provenance attached to an observation must survive every model-facing memory stage where that observation may influence persistent memory.

At minimum, preserve the distinction between:

- `grounded_result` — authoritative evidence of tracked state/action outcome;
- `narrative_only` — literary/social observation that is not proof of tracked state change.

Equivalent existing names may be used if the codebase already has canonical constants/enums.

Do not create duplicate authority concepts if one already exists.

---

## Hard rule: Never parse narration

Narration must **not** be parsed deterministically to infer whether a tracked action "really" happened.

Do not add:

- regex rules;
- keyword matching;
- phrase classifiers;
- English-language action extraction;
- heuristic narration-to-action mapping.

The engine already knows the provenance of the observation at creation time.

Preserve that structured provenance instead of trying to reconstruct it from prose later.

---

## Required behavior

### 1. Preserve authority on stored/verbatim observations

Where a model-facing or memory-facing observation is created from Character narration or a grounded engine result, retain the authority/provenance field through the stored observation representation used by later memory stages.

A narration observation must remain marked non-authoritative.

A grounded result must remain marked authoritative.

Do not silently drop the field while building:

- verbatim observations;
- complete verbatim snapshots;
- consolidation inputs;
- retrieval-maintenance inputs;
- any intermediate normalized memory event representation.

---

### 2. Memory-maintenance prompts must expose provenance

When memory-maintenance/consolidation models receive observations, the prompt/protocol must make the authority distinction visible and concise.

The intended meaning:

> `grounded_result` may be used as evidence that a tracked world-state change occurred.

> `narrative_only` records what was narrated, said, shown, or apparently intended, but is not by itself evidence that a tracked world-state change occurred.

The instruction must not require the model to parse prose to determine authority.

Authority is supplied structurally by the engine.

---

### 3. Narrative observations may still be remembered

Do not discard `narrative_only` observations wholesale.

They may contain valuable memory material:

- dialogue;
- lies;
- promises;
- threats;
- jokes;
- tone;
- emotion;
- apparent intentions;
- gestures;
- social interactions;
- subjective interpretations.

The model may remember them in appropriately qualified form.

Example:

Allowed:

> Garrick said or appeared to present the Banush.

Not allowed solely from `narrative_only` provenance:

> Garrick formally served the Banush and the Traveler received it.

If a matching grounded result exists, the memory system may of course remember the canonical event normally.

---

### 4. Grounded results remain authoritative

Memory maintenance must be able to use `grounded_result` observations as evidence of tracked events.

Examples include successful formal operations such as:

- movement;
- item transfer;
- item placement;
- money transfer;
- fill/pour;
- consumption;
- lock state changes;
- serving food;
- writing/content mutation;
- other tracked deterministic mechanics.

Do not weaken grounded-result memory just to solve narration contamination.

---

### 5. Conflicts resolve in favor of canonical/grounded evidence

If the memory-maintenance input contains:

- narration claiming a tracked change;
- grounded/canonical evidence showing that the change did not occur or that current state differs;

the resulting memory must not promote the narration into canonical tracked fact.

The system does not need to erase the narration.

It may retain the social fact that the Character said or implied something.

But canonical/grounded evidence dominates tracked-state interpretation.

---

### 6. Keep the existing Character contract behavior

Do not change the current Character action/narration scheduling rules as part of this patch.

In particular, do not modify:

- `available_actions`;
- `relevantMechanics`;
- `continuation` semantics;
- `serve_food`;
- action-source gating;
- validators;
- repair logic;
- action executors.

This patch is specifically about provenance surviving into memory.

---

## Regression tests

### A. Narrative-only false transfer/placement does not become canonical memory

Construct a model-facing observation sequence where:

- narration claims an item was transferred or placed;
- no matching formal tracked action succeeded;
- canonical state still shows the original ownership/location.

Run the memory-maintenance/consolidation path.

Assert:

- provenance remains `narrative_only` throughout the relevant input path;
- generated memory does not assert the tracked transfer/placement as canonical fact;
- qualified memory of the narration itself remains allowed.

---

### B. Grounded transfer does become memory

Construct the equivalent scenario with a successful formal tracked transfer.

Assert:

- the grounded observation reaches memory maintenance as `grounded_result`;
- resulting memory may correctly state that the transfer occurred.

---

### C. Mixed narrative + grounded evidence

Provide:

- narration claiming a tracked result;
- grounded evidence representing the actual outcome.

Assert that consolidation follows grounded evidence for tracked state.

---

### D. Safe narrative memory survives

Use dialogue or an untracked gesture marked `narrative_only`.

Assert that memory maintenance may still preserve the social/literary content.

The fix must not turn `narrative_only` into "ignore this observation."

---

### E. No deterministic narration parser

Tests/code review should confirm that the implementation does not introduce any natural-language parsing or phrase matching to classify tracked actions from narration.

---

## Documentation

Update the canonical engine/memory documentation to establish:

> Observation authority/provenance survives into memory maintenance.

And:

> Narration is not a second world-state store. It may be remembered as narration/social evidence, but tracked canonical facts require grounded/canonical evidence.

Also preserve the project rule:

> Free-form narration is never deterministically parsed to infer tracked actions or state changes.

# Part II — World: Chuhaister Eye Appearance

## Required world change

Update Chuhaister's authored description so that:

- his eyes are **blue**;
- they are normally blue without requiring a constant supernatural glow;
- he can make them **glow brightly at will**;
- he may intentionally use the glow to emphasize something in speech or presence.

The glow is:

- voluntary;
- expressive;
- not constant;
- not an automatic emotional reaction;
- not a separate formal action/mechanic unless such a mechanic is explicitly designed later.

The purpose of this change is to prevent Character models from filling the unspecified eye color with invented details such as amber eyes.

---

## World scope

Update the appropriate canonical world-facing fields used by Character/narrative generation.

If both public and private world variants contain independent authored Chuhaister descriptions, keep them consistent.

Do not otherwise alter:

- Chuhaister activation;
- summoning;
- movement restriction;
- food behavior;
- sopilka ability;
- disappearance lifecycle;
- discovery/secret mechanics;
- Character mind.

---

# Acceptance Criteria

The finalization patch is complete when:

1. `grounded_result` vs `narrative_only` authority survives through the memory-maintenance/consolidation path.
2. Memory models are explicitly told what that structured authority means.
3. Narrative-only observations cannot become unqualified canonical tracked facts solely because of their prose content.
4. Narrative/social content can still be remembered in qualified form.
5. Grounded tracked events continue to consolidate normally.
6. No deterministic parsing of narration is introduced.
7. Chuhaister's authored eyes are blue.
8. Chuhaister may voluntarily make his blue eyes glow brightly for emphasis.
9. No unrelated gameplay/retrieval/intimacy changes are introduced.
10. The full existing test suite passes.
11. The public build passes the normal release-profile checks and is ready for itch.io publication.

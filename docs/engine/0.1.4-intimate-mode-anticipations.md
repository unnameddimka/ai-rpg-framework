# Mallowstead 0.1.4 — Intimate Mode and Directed Anticipations

**Status:** Implementation specification  
**Layer:** Engine  
**Target version:** `0.1.4`

## 1. Purpose

Add a character-driven intimate-context mode that gives Character models initiative during explicitly romantic or otherwise intimate scenes without introducing explicit intimate engine actions.

The engine must not infer intimate state, fulfillment, or protocol compliance by parsing free-form narration. Narration remains non-authoritative prose. All tracked intimate-mode changes are model-authored structured output validated by the engine.

## 2. State model

Intimate state is:

- per character;
- per partner;
- directional;
- able to support multiple simultaneous partners.

`Mara -> Traveler` and `Traveler -> Mara` are separate contexts.

Each active directed `character -> partner` context contains **exactly five anticipations**.

Conceptual shape:

```js
world.ai.intimateContexts = {
  [characterId]: {
    [partnerId]: {
      anticipations: [ /* exactly five strings */ ]
    }
  }
}
```

Exact field placement/naming should follow current runtime continuation-state conventions.

This state is persistent runtime continuation state. It is not STM, LTM, a belief, a relationship, a known fact, or canonical world truth.

## 3. Anticipations

An anticipation is one concrete thing the character currently hopes to do, receive, express, evoke, notice, feel, or experience during the current intimate encounter.

Anticipations may be physical, emotional, conversational, relational, or sensory.

Examples:

- hear a sincere compliment;
- make the partner feel safe;
- feel valued or appreciated;
- notice whether the partner relaxes;
- express something personal;
- experience a particular affectionate gesture.

They are not a quest checklist and need not all occur.

Prompt guidance should communicate approximately:

> Anticipations are five concrete things this character currently hopes to do, receive, express, evoke, notice, or experience during this intimate encounter. They are not a checklist and need not all occur. Use them to give the character initiative rather than merely reacting to the partner.

## 4. Enabling intimate mode

Intimate mode is enabled only through explicit structured Character-model output.

The engine does not scan narration for romantic or intimate wording.

When an ordinary Character decision enables a new `character -> partner` context:

1. validate the requested partner against grounded character context;
2. perform a Utility semantic-memory retrieval preflight;
3. retrieve the full bodies of selected memories through the existing retrieval architecture;
4. perform a dedicated Character-model anticipation-generation request;
5. require exactly five valid anticipations;
6. commit the new intimate context only after successful validation.

Enable is atomic. Failure, stale context, invalid output, or failed repair must not leave a partially-created context.

## 5. Initial anticipation request

The generation request receives at minimum:

- normal grounded character identity/personality;
- current scene and target-partner context;
- relevant recent observations/dialogue;
- selected full memories from retrieval;
- ordinary beliefs/relationships as appropriate;
- every other already-active intimate context for the same character as read-only context.

The new target's anticipations cannot be used by its initial retrieval preflight because they do not exist yet.

## 6. Multiple partners

A character may have multiple simultaneous partner contexts.

Example:

```text
Mara -> Traveler : 5 anticipations
Mara -> Nell     : 5 anticipations
```

When generating or updating `Mara -> Traveler`, the model may see `Mara -> Nell` so it can understand the whole encounter.

However:

- every stored list remains target-specific;
- no list is automatically copied between partners;
- one Character response changes only partner records it explicitly updates.

## 7. Ordinary Character decisions

While intimate mode is active for a character, the ordinary Character decision request receives all of that character's active partner contexts and their current anticipations.

This state is motivational context intended to increase initiative.

The feature does not create special explicit intimate/18+ engine actions. Ordinary formal actions remain authoritative for tracked mechanics; intimate scene content may occur in narration.

## 8. Updating anticipations

The Character model may semantically judge from current narration/context that an anticipation:

- was fulfilled;
- became irrelevant;
- evolved;
- should be replaced.

The engine must not make that judgment from prose.

Use the simplest robust structured contract compatible with the current Character response architecture. A complete target-specific replacement list of exactly five is acceptable. An equivalent `keep / fulfilled / drop / replace` contract is also acceptable if it integrates more cleanly.

After every successful update, every active directed context still contains exactly five live anticipations.

Do not maintain a persistent fulfilled-history list. Fulfilled or obsolete anticipations leave the live set and may be replaced.

## 9. Semantic retrieval integration

Ordinary semantic-memory retrieval preflight for a Character with active intimate contexts receives the character's active anticipations as compact query context.

This permits relevant old memories to be selected because of the character's present hopes.

Anticipations are retrieval context, not evidence and not memory themselves.

## 10. Disabling

A Character model may structurally disable intimate mode for a specific partner.

Disabling removes only that directed relation.

It does not automatically remove:

- the reverse `partner -> character` relation;
- another partner context;
- another character's state.

## 11. Timelapse

Entering any timelapse clears all active intimate contexts and anticipations deterministically.

Prefer clearing before timelapse model/planning context is built so transient encounter motivation does not leak into coarse-time simulation.

## 12. Save/load and migration

Active contexts persist through ordinary save/load.

A mid-encounter save restores the same directional contexts and five anticipations per context.

Older saves without intimate state migrate to an empty structure.

## 13. Privacy and grounding

A Character request receives only that character's own intimate contexts.

One character's private anticipations must not be exposed directly to another character merely because they are present in the same scene.

Other characters may infer desires only through ordinary perception, dialogue, memory, and relationship reasoning.

## 14. Adult scope

Intimate mode is for adult characters only.

Do not activate it for a character authored as a minor.

## 15. Architectural invariant: no narration parsing

Do not add:

- regex;
- keyword/phrase matching;
- deterministic prose classifiers;
- sentiment analysis;
- narration-derived state inference.

Narration is non-authoritative prose. The model may semantically interpret it and return structured intimate-state changes; the engine validates only that structured output.

## 16. Regression coverage

Add tests covering at least:

1. `A -> B` and `B -> A` are independent;
2. every active relation has exactly five anticipations;
3. one character may have two active partners simultaneously;
4. initial enable performs retrieval then anticipation generation before commit;
5. failed generation leaves no active context;
6. other active partner contexts are included as read-only generation/update context;
7. ordinary retrieval preflight receives active anticipations;
8. structured updates may replace fulfilled/obsolete anticipations while preserving exactly five;
9. disabling one target does not disable others or reverse direction;
10. ordinary save/load preserves active state;
11. timelapse clears all active intimate state;
12. one character never receives another character's private anticipation list;
13. no deterministic narration parser is introduced.

## 17. Non-goals

This patch does not add:

- explicit sexual action mechanics;
- body-part simulation;
- relationship thresholds for intimacy;
- deterministic romance detection;
- fulfilled-anticipation history;
- a generic desire/personality engine;
- automatic coupling between the two directions of a relationship.

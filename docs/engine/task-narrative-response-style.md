# Task: Narrative Response Style for AI Characters

## Base Version

Implement this task on top of:

`ai-rpg-framework(20260808-115840).zip`

## Goal

Make normal AI-controlled character responses feel like moments in an ongoing role-playing scene instead of primarily looking like terse protocol/action-selection output.

This is a prompt-level behavior change only. Do not change the world-state authority model, action protocol, response schema, scheduler, memory model, or character authoring schema.

## Prompt Layers

Preserve the existing separation between:

1. the shared technical AI protocol prompt generated by `src/23-ai-protocol.js`; and
2. character-specific authoring data such as `character.aiDescription` from `data/world.json`.

The shared technical prompt defines general role-playing response behavior for every AI-controlled character.

`character.aiDescription` remains responsible for the character's particular identity, personality, priorities, and voice. Do not copy those authoring instructions into the shared prompt and do not add new narrative-style fields to `world.json` for this task.

## Shared Narrative Style Contract

Add a concise shared style instruction to the technical system prompt.

The instruction must communicate the following behavior:

- Treat each response as part of an ongoing role-playing scene, not merely as action selection or protocol completion.
- When natural, use `publicNarrative` for brief visible behavior such as expression, posture, gesture, hesitation, attention, or other atmospheric detail that other characters could perceive.
- Use `spokenText` for natural dialogue in the controlled character's own voice, guided by the supplied character description, memories, beliefs, relationships, and current situation.
- Prefer concrete, characterful phrasing over generic assistant-like or functional NPC replies.
- Keep responses concise by default. Usually one or two short narrative sentences plus dialogue is enough when both are useful.
- Do not force narration or speech into every response. Silence, `null`, or an action-only response remains valid when it is natural for the character or situation.
- Do not repeat information merely to make the response longer.

## Grounding Constraint

Narrative style must not weaken deterministic grounding.

When the model selects a formal action, it may narrate accompanying non-state-changing behavior, preparation, expression, or intent, but it must not narrate or state that the formal action successfully changed the world before the engine confirms the result.

Examples of safe accompanying narration before execution:

- looking toward the mug cabinet;
- wiping hands on a rag;
- reaching toward a shelf;
- shifting posture before moving;
- speaking while beginning a task.

Examples that remain forbidden before grounded confirmation:

- stating that the mug was successfully taken when `take_item` has not yet executed;
- stating that ale was successfully poured when `fill` has not yet executed;
- stating that an item was successfully handed over when `give_item` has not yet executed.

The existing grounded-result rule remains authoritative.

## Scope

Expected source changes:

- `src/23-ai-protocol.js`
- `tests/run-ai-tests.js`
- this specification under `docs/`

Do not modify:

- `data/world.json`;
- character `aiDescription` values;
- the response JSON schema;
- action execution mechanics;
- scheduler behavior;
- memory schema;
- generated world data;
- `dist/game.html`.

## Acceptance Criteria

- The shared technical system prompt explicitly frames AI responses as role-playing scene responses rather than mere action selection.
- The prompt explicitly describes appropriate use of `publicNarrative` and `spokenText`.
- The prompt asks for character-specific, concrete dialogue rather than generic assistant-like replies.
- The prompt gives a concise default target rather than encouraging long prose.
- The prompt explicitly preserves silence and `null` as valid outputs when appropriate.
- The prompt preserves the existing rule against claiming unconfirmed formal-action results.
- The decision response schema remains exactly `action`, `publicNarrative`, `spokenText`, and `memoryUpdates`.
- Existing one-action and multi-step behavior remains unchanged.
- Existing AI integration tests continue to pass.

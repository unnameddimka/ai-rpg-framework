# Task: Unified Intents and Single-Request AI Reaction Waves

## Status

Implemented on top of `ai-rpg-framework(10).zip`.

## Goal

Replace independent narrative/action controls and the immediate two-request AI action cycle
with one shared intent format and a deterministic user-triggered reaction wave.

## Implemented contract

### Unified intent

Human and AI controllers submit one envelope containing:

- optional narrative text;
- optional addressee and noticeability;
- zero or one formal action.

At least narrative text or a formal action is required. Narrative and formal-action events
share one `interactionId`. Objective consequences come only from the formal action result.

### Player controls

The debug interface now provides:

- one full-width narrative text area;
- addressee and loudness selectors;
- radio buttons for `No formal action` or one available action;
- one **Submit** button;
- one **Pass / Next turn** button.

### Reaction-wave scheduler

After a normal Submit, the scheduler processes a full reaction wave unless the sidebar
checkbox **Stop automatic AI request processing** is enabled. Pass explicitly runs a wave
even while automatic processing is paused. Sidebar and sphere controls still process one queue
head for debugging.

Within a wave:

1. direct addressees and formal-action targets are prioritized;
2. every AI character may react at most once;
3. later characters see grounded events generated by earlier reactions;
4. new observations for already-reacted characters remain queued for the next wave;
5. any provider/protocol/commit failure stops the wave and preserves the failing queue entry.

### Single AI request

One AI request returns optional narrative, optional speech, bounded memory updates, and at most
one formal action. The engine executes that action locally. There is no immediate second
`game-result` request. Success/failure is stored as an ordinary observation and may be
interpreted during a later wave.

### Turn narrative

The player-facing location view shows a **Latest turn** block assembled in causal order from:

- the human intent;
- grounded human action events;
- AI narrative/speech;
- grounded AI action events.

No extra narrator-model call is made. When automatic processing is enabled, a movement Submit
finishes the reaction wave before the destination passage renders.

## Non-goals for this milestone

- timer-driven or background AI;
- more than one formal action per intent;
- shout propagation across locations;
- a separate narrator/summarizer model;
- interruptible/deferred movement transactions;
- repeated activation of the same AI character inside one wave.

## Validation

The deterministic tests cover combined observations, radio-button UI, Submit/Pass behavior,
auto-processing pause, direct-target priority, once-per-wave activation, causal visibility of
earlier reactions, deferred observations, single-request AI actions, and absence of live
`game-result` requests.
